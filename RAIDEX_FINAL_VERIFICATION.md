## Security/data-integrity fixes found and closed in this pass

1. **`/admin/system-health` NameError** — every real (non-test) call to this endpoint would have crashed with a 500 due to the undefined `EMERGENT_LLM_KEY` reference. Zero prior test coverage let this ship. Fixed + covered.
2. **Subscription creation race** — `create_subscription`'s conflict-check-then-insert was not originally atomic (two concurrent requests for the same vehicle could both pass the availability check). Closed using the exact same Mongo-transaction-with-non-transactional-fallback pattern the booking engine already uses (`BookingService.create_booking`), so the invariant "a vehicle cannot be allocated to incompatible overlapping subscriptions/bookings" (spec §41) actually holds under concurrency, not just in the happy path.
3. **Vehicle-swap double-allocation race** — `complete_swap` originally set `available: False` on the new vehicle with a plain `update_one`, so two concurrent swaps targeting the same vehicle could both "win". Changed to an atomic `find_one_and_update({"available": True}, {"$set": {"available": False}})` claim; the loser now gets a 409 instead of silently overwriting the winner's allocation. Covered by `test_complete_swap_rejects_if_new_vehicle_lost_availability_meanwhile`.
4. **GPS provider startup-crash risk** — the first draft of `get_gps_provider()` raised `RuntimeError` on any unrecognized `GPS_PROVIDER` value, which would have crashed the entire app at startup (since `inject_db` calls it during the FastAPI startup hook) over a simple env-var typo. Changed to log-and-fall-back-to-phone, matching every other provider factory's established convention in this codebase (payment/KYC/damage-inspector all fail-safe, not fail-loud, on an unknown value).
